# Soul Vessels — Decision Log

Decisions made while building, logged so the design docs and the code agree. The addendum
(`design-addendum-v1.md`) wins over the bible; this log wins over both for *implementation*
choices, never for game rules. Each entry: what, why, how to undo.

| ID | Date | Decision | Why | Undo cost |
| --- | --- | --- | --- | --- |
| D-001 | 2026-11-13 | Godot project lives at the repo root (`project.godot`), code in `src/`, data in `data/`, assets in `assets/`, tests in `tests/`. Non-game folders get a `.gdignore`. | The studio template's Godot row (`engine.code_root: src`) and its `commands.run` (`godot --path .`) assume a root project. | Low: move files, fix `res://` paths. |
| D-002 | 2026-11-13 | Renderer `mobile`, physics `Jolt Physics` set explicitly, physics 60 Hz, physics interpolation on. | User asked for the Mobile renderer. Jolt is the 4.6+ default and faster; `DEFAULT` may change. Interpolation removes camera jitter on 90/120 Hz phones. | Low. |
| D-003 | 2026-11-13 | Every tuning number lives in JSON under `data/balance/` (`combat.json`, `vessels/*.json`, `enemies/*.json`), loaded by a `Balance` autoload into typed dictionaries. | Coding standard: data-driven, never hardcoded. The kit skills (`playtest-bot`, `feature-breaker`) already point at `data/balance/`. | Low. |
| D-004 | 2026-11-13 | 2.5D = 3D scene, perspective `Camera3D` (FOV 35°, ~14 m back) looking down -Z, player locked to the X/Y plane at z = 0, parallax from real depth layers at z = -6/-14/-30. | Perspective gives free parallax and real lights; the addendum asks for 3D environments with a side-on camera. | Medium: an orthographic swap changes layer spacing. |
| D-005 | 2026-11-13 | Unit tests run on a small in-repo runner (`tests/run_tests.sh` → `tests/runner/test_runner.gd`), not gdUnit4. | gdUnit4 is a download; the user did not ask for it and the runner needs ~100 lines. Switch to gdUnit4 any time: tests are plain `assert`-style functions. | Low. |
| D-006 | 2026-11-13 | Placeholder music stems are synthesised offline to WAV by `tools/audio/synth_stems.py` (pure Python, no numpy) with the addendum's exact stem names; Godot imports them (QOA compression). Real OGG stems replace the files, same names. | No ffmpeg or numpy on this machine; the code must not change when real audio arrives. | None: drop in OGGs with the same names. |
| D-007 | 2026-11-13 | Android package `com.soulvessels.chapter1`, debug keystore generated with the bundled JDK into `engine/godot/editor_data/keystores/debug.keystore` (gitignored). `export_presets.cfg` is committed (no secrets; Godot keeps credentials in `export_credentials.cfg`). | Headless export needs a keystore it can find without the editor UI. | Low: rename package before any store upload. |
| D-008 | 2026-11-13 | The Branded Warden's "flanked by Nyra" and "shattered by Darius" shield rules are implemented as data: the shield blocks 80 % of damage from the front arc (±60°); any attack from behind ignores it; `Crushing Blow` sets `shield_broken`. Caelan's Counterstrike opens a 2 s guard break (addendum). | M1 has Caelan and Nyra only; the rules must already be the real ones. | None. |
| D-009 | 2026-11-13 | The bare `python` on this PC is Microsoft's Store alias stub. Scripts call the real interpreter at `C:/Users/ACHRAF CHARKAM/AppData/Local/Programs/Python/Python312/python.exe` via `tools/python.sh`. | `python`, `python3` and `py` all fail in Git Bash; the template's yaml-helper hooks degrade to defaults. | None: turn off the alias in Windows Settings > Apps > App execution aliases and the plain name works. |
| D-010 | 2026-11-13 | Gamepad mapping follows the addendum: X attack, A jump, B dodge, Y ability 1, RT ability 2, LT+RT ultimate, LB/RB swap, D-pad up flask. Keyboard for desktop testing: WASD/arrows, J attack, Space jump, K dodge, U/I abilities, O ultimate, Q/E swap, F flask, F3 debug HUD. | Desktop testing needs a keyboard layer the design never specified. | None. |
| D-011 | 2026-11-13 | Hits are rectangles in the X/Y play plane, resolved by a `CombatWorld` registry, not Area3D overlaps. Bodies of the player and enemies do not collide with each other (they collide with the world only). | Side-on with z locked, a rect is exact, deterministic, order-independent and testable headless; no body blocking means no getting stuck in a swarm and lets Shadowstep pass through enemies. | Medium: swap `ActionHit.sweep` for Area3D queries. |
| D-012 | 2026-11-13 | Enemy death is a 0.4 s shrink-and-sink, not an alpha dissolve. | Alpha would add transparent pipelines compiled at death time (a hitch); final VFX replace it. | None. |
| D-013 | 2026-11-13 | The shared Combat stem plays Track 06's 140 BPM drive as 16th notes on the zone's 70 BPM grid. | All stems of a zone must share one tempo to sit in one `AudioStreamSynchronized`; double-time keeps the "140" feel. | None: real stems follow the same rule. |
| D-014 | 2026-11-13 | The music clock follows the audio playback position (loop-counted), with real time only when nothing is mixing. | It is what the player hears, it survives hitstop (`Engine.time_scale`) and frame hitches, and Movie Maker renders audio in game time. Measured drift in play: 0.046 s. | None. |
| D-015 | 2026-11-13 | The **debug** Android preset requests INTERNET so the playtest bridge can listen on 127.0.0.1 (Android needs it even for localhost). The release preset (M5) must not. | Found on the first emulator boot: the bridge socket failed. | None. |
| D-016 | 2026-11-13 | Sync Guard order: an unblockable hit checks evade guards (Nyra) before a lethal hit checks intercept guards (Caelan); the active Vessel is asked first, then the others. Each spends 1 bar and locks that Vessel's guard for 90 s. | The addendum gives each guard its trigger but no priority; evading costs nothing extra and keeps HP. | None (data: `sync_guard.trigger`). |
| D-017 | 2026-11-13 | The Watcher beam ticks every 0.25 s for 1.5 s at the data's motion value; a Caelan perfect parry on any tick reflects it (Watcher takes its own ATK) and ends the beam. | The addendum gives "ATK 30 (beam)" but no tick rule. Full exposure ≈ 6 ticks ≈ 120 HP against Caelan: a real threat, not a wall. | None: `tick_s`, `motion` in the JSON. **Provisional tuning.** |
| D-018 | 2026-11-13 | Commons flinch when hit outside their attack; elites have poise. Final Stand knocks everyone down. | Souls-like readability: trading hits with commons is safe, with elites it is not. | None. |
| D-019 | 2026-11-13 | The Branded Warden turns 0.6 s after the player crosses behind it. | The addendum makes flanking a counter ("flanked by Nyra"); an instant turn would make the back unreachable. | None (`turn_delay_s`). **Provisional tuning.** |
| D-020 | 2026-11-13 | The sandbox sets every Vessel's Affinity to 3 (`data/balance/sandbox.json`) so Sync Guard and Sync Ultimate are testable in M1. | Affinity is earned in M2; M1 must exercise the whole kit. | None. |
| D-021 | 2026-11-13 | Placeholder characters use the bible's colours lifted 15–22 % with a rim light; enemies get one shadow-casting part each, the player its torso and legs. | Readability on a dark cavern (bible: high-contrast mobile combat) and the draw-call budget (119 with 5 enemies). | None: final art replaces `VesselVisual`/`EnemyVisual`. |
| D-022 | 2026-11-13 | The Soul Gauge counts as "in combat" while any enemy has aggro, not only after hits. | "Drains 1/s outside combat" (addendum); draining while a Crawler is mid-chase broke whole bars and blocked Sync Guards (playtest finding). | None. |
| D-023 | 2026-11-14 | Rooms are text grids in `data/world/zone1.json` and `zone2.json`, 1 character = 1 m (legend in `src/world/room_data.gd`). A greedy merge turns rock into few large boxes; rock touching the room edge is deep (to z = -4.5), floating rock shallow (to z = -2.2) so it reads as a ledge; decor is generated per theme from a seed of the room id. Exits are digit cells at the edge; each exit names the target room's exit, and the player arrives one metre inside it (data may override). | 30 rooms by hand had to be quick to write, diff and check: a test proves every exit links back and every arrival point is open space. One room in the tree at a time keeps memory and draw calls flat (about 30 draws per room). | Medium: the grid stays the source even if rooms later become scenes; a converter would read it. |
| D-024 | 2026-11-14 | Resting at an altar: full HP and flasks, stamina and posture reset, ordinary enemies everywhere return (`killed_commons` cleared), killed elites and cleared arenas never return, the altar becomes the respawn point and Continue's checkpoint, then the game saves. The loadout changes only at altars. A Vessel memory read at an altar gives that Vessel +1 Affinity once. The altar menu pauses the game and plays Track 02. | Addendum "Soul Altars" and "Affinity". Souls-like rest: the world resets, progress does not. | None. |
| D-031 | 2026-11-14 | 6/8 tracks count the dotted quarter as the beat: Track 03 is 84 BPM, 2 beats per bar, 16 bars (22.9 s), so the 4-bar boundary is 5.71 s. Zone 2 keeps Zone 1's falling cadence a fourth up (Dm C Bb A) so every Vessel's leitmotif stem plays the same melody. Title and altars share Track 02 (60 BPM 3/4, solo piano, bed stem only). | The addendum gives "84 BPM 6/8" without saying which note gets the beat; the dotted quarter is how 6/8 is felt and keeps transitions under 6 s. | None: `bpm`, `beats_per_bar`, `bars` in `music.json`. |
| D-026 | 2026-11-14 | Loot: one roll per kill. An enemy's own `drops` table (per rarity, weighted) wins; a rarity it does not list uses the zone pool in `data/progression/loot.json`. Lore items (Faded Parchment, Echoing Relic) become the next unread entry of their kind, or Essence once all are found. Drops pop out and home in on the player after 0.8 s, so loot is never left behind a door. Rarity shows as colour and as a word (colour-blind safe). | The addendum gives tier odds and the bible gives per-enemy lists; this joins them. Budget: a Crawler gives a Lesser Soul Shard 8.2 % of the time, a Watcher 12.3 %, so a first pass through Zones 1-2 yields about 6-8 shards plus 6 placed ones. | None: all in JSON. |
| D-032 | 2026-11-14 | Vessels and enemies are 2D sprites cut from the user's concept sheets, standing in the 3D rooms (`SpriteBody`). One pose per figure; a vertex shader steps the legs, leans, squashes and sways it, and effects carry the action (weapon arc, guard glow, afterimages, dust, soul-burn). Sprites are alpha-scissored (they write depth), about 60 % self-lit, and sit at small depth offsets so overlaps never flicker. Camera moved in from 14 m to 11.5 m. | The user rejected the primitive bodies and asked for their designs. The kit's 3D route needs Blender and paid generators that are not on this PC; the paintings themselves give exact fidelity today, and the visual interfaces were built to be swapped. | Low: `VesselVisual.build` and `EnemyVisual.build` pick the sprite when one exists; delete a sprite entry and the primitive returns. Real frame animation needs extra poses from the artist. |
| D-033 | 2026-11-14 | Rooms are dressed after the zone paintings: the painting itself is the far backdrop (unshaded, outside the fog, tinted darker), surfaces use generated tileable textures applied in world space (triplanar), decor is seeded code-built geometry merged per material, plus two mist bands, light shafts, motes and a full-screen vignette. Gates and altars get their own shapes (`GateLook`, `Altar`). Enemies are kept inside a room by side walls only they collide with. Menus use a serif face loaded from the device (`SystemFont`), so no font file ships. | Follows the user's zone paintings while keeping real parallax, lights and fog (addendum: 3D environments, side-on camera). Triplanar avoids UV work on generated meshes. | Low: every texture and painting is a file that can be replaced; `themes.json` holds the colours. |
| D-027 | 2026-11-14 | Soul Core layout: 20 nodes in five branches from a Core Heart: Vitality (+15 HP, 5 nodes plus the heart), Endurance (+5 % stamina regen, 4), Resonance (+10 Soul Gauge cap, 4), Vessel (+1 flask charge, 3: 3 to 6 charges), Mercy (+5 % of max HP per flask, 3, each needing the Vessel node above it). Every node costs 1 Lesser Soul Shard. Buying saves at once; max HP gained is healed and new flask charges arrive full. | The addendum gives the node count, the cost and four effects "etc."; flask healing is the fifth so the last 3 nodes do not repeat a branch. About 14 of 20 are reachable in Chapter I, so the player chooses a build. | None: `data/progression/soul_core.json`. |
| D-028 | 2026-11-14 | Affinity XP: 0.6 per second in combat, 4 per kill, 40 per elite kill, 6 per perfect parry, 4 per perfect dodge, all to the active Vessel. Levels at 40 / 120 / 300 / 650 / 1100 XP. Level 1 turns that Vessel's memory into lore; reading it at an altar adds one whole level, once. Sync Guard at 2 and Sync Ultimate at 3 (from `combat.json`). | The addendum names the sources and what each level unlocks but no numbers. Tuned so a first pass of Zone 1 (about 40 kills, 5 minutes in combat) brings Caelan to level 3 just before or at the Warden; Nyra reaches 2-3 by the end of Zone 2. **Provisional tuning.** | None: `data/progression/affinity.json`. |
